# Changelog

Notable changes to the skills catalog are recorded here. Versions apply to the
whole catalog, not individual skills. A version is published only when its
matching Git tag exists.

## Unreleased

- Extended `review-codebase-architecture` with implicit-state-machine and lifecycle-analysis triggers plus an on-demand reference for tracing state ownership, transitions, recovery, and observable UX/DX/AX trade-offs. Retained report-only discovery and design approval; no automatic library, verifier, or refactoring workflow.

- Added change-coupling analysis to `deslop` and `review-codebase-architecture`, selectively adapted from `caldoai/skills`'s `untangle-codebase`: group related cleanup symptoms under root-cause proposals and examine hidden links, needless coupling, and dependency volatility. Retained bounded scope, behavior preservation, and design approval gates; no new skill or automatic refactoring loop.

## 0.3.0 - 2026-11-09

- Added a distinct herdr-core (`hc`) Pi host adapter: admit fresh workers and reviewers in separately verified Herdr-app tabs, with worktree, model, and lifecycle checks; retain the older Herdr pane adapter. Live app/version compatibility is not yet qualified. Model defaults remain worker `zai/glm-5.3`/`high` and reviewer `openai-codex/gpt-6.1-sol`/`high`; installed settings are unchanged.
- Selectively refreshed `drawio-skill` from its maintained standalone source: portable desktop CLI resolution, structured validator diagnostics, moved/rerouted diagram diffs, importer provenance, embedded SVG images, icon URL checks and export/documentation fixes. Preserved the local pipeline and MIT attribution; new upstream IR/MCP tooling is not bundled. Added a focused validator regression.
- Updated `grilling` question wording and fresh-context delegation guidance in `grilling` and `research`. Audited all recorded source relationships; documented the still-open coordinated Archify and last30days runtime upgrades without replacing local adaptations or approval gates.

## 0.2.0 - 2026-11-06

- **Breaking:** Retired the separate `simplify-code` skill and consolidated settled-change and broader cleanup under `deslop`. Reuse, Quality, and Efficiency remain perspectives in one bounded pass; additional reviewers are opt-in or project-required, with the full contract in an optional reference. Updated callers, tests, source relationships and migration guidance. Existing installed copies require manual migration; runtime routing evaluations remain unrun.

- Reworked `deslop` into a behavior-preserving KISS workflow for diffs, files, directories, and projects: concrete proposals and user selection by default; explicit direct cleanup proceeds without another selection round. Added selected-proposal handoff to the existing design/ADR/plan/ticket workflow, removed blanket validation and per-edit check defaults, and aligned README/agent routing with the unified cleanup entrypoint.

## 0.1.0 - 2026-11-06

- Added `project-formal-verification`, an explicitly requested creator/maintainer for project-local invariant, model-check and code-proof recipes, with bounded negative controls, code/model correspondence and no implicit installation or product-repair authority. Planning, shaping, orchestration briefs and completion claims now distinguish formal scope from empirical evidence without adding a mandatory verification stage. Clarified the existing empirical recipe's isolation, stand-in limits, dry-run effects, readiness recovery and retained evidence. Pinned the new pstack adaptations and preserved the existing normal-verification pins; runtime routing and a product pilot remain unqualified.

- Verification-first planning and orchestration: `write-implementation-plan` now plans empirical verification of the real artifact (per `project-verification`, preferring an installed `verify-<project>` recipe) before tests — new tests only for regression risks that outlive the plan, thorough verification once in a final verification task after all implementation tasks, and adversarial review as a scoped exception (written-convention conformance, high-risk integration effects, explicit requirement) instead of a per-unit default. `orchestrate-implementation` accepts on verification plus parent inspection, dispatches independent reviewers only where execution evidence cannot reach, and runs the plan's final verification task on the assembled candidate; the `merge-worktree` candidate handoff names the exact verified range, final verification evidence, and only required review evidence.

- Added `land-changes` (workflow): one approved end-to-end landing sequence — commit intended residue, integrate through `merge-worktree`, push with verified remote SHAs, close the named issues with acceptance evidence (`gh`, or Epiq `epiq_*` tools when configured), then clean up source and run worktrees and return BB/Orca environments via their adapters. Single landing-plan approval; cleanup never precedes a verified push; failed or uncertain work is preserved and reported.

- `orchestrate-implementation` now auto-detects the BB and Orca harnesses from session environment (`BB_THREAD_ID`; `ORCA_PANE_KEY`/`ORCA_TAB_ID`/`ORCA_WORKTREE_ID`) and dispatches through new `bb-dispatch` (BB child threads on `--parent-self` worktree environments, provider pi) and `orca-dispatch` (`orchestration worker-start --agent pi`, wake-driven send/reply coordination) adapters; Orca-owned placement replaces parent allocation there. Supervision became light by default: the human is interrupted only for critical decisions (irreversible/destructive actions, target integration/publication authority, material scope or authority changes, blocking conflicts, contract-required approvals); strict stage-by-stage confirmation applies only on explicit request. Non-critical choices proceed on the smallest safe default and are reported at handoff.

- Dieted the `workflow` category skills: removed duplicated ideas (evidence-reuse rule stated once in `merge-worktree`; ADR criteria and context-ownership rules only in `domain-modeling`; probe-report filing only in `prototype-question`), trimmed the always-loaded `verification-before-completion` description, and tightened repeated prose in `make-release`, `write-implementation-plan`, `planning-contract`, `shape-design`, and `grilling`. No workflow, gate, pinned contract string, or attribution changed; `orchestrate-implementation`, `capture-project-vision`, `prototype-question`, and `review-codebase-architecture` were checked and left at weight. Changed skill files shrank about 3.5 KB (roughly 5%).

- Selectively refreshed upstream skill guidance: concise, observable skill triggering; mutation-backed debugging evidence; safe Herdr wait retries; voice-preserving humanization; Python display metadata; LiteParse image extraction; and Draw.io geometry/render checks. Documented Draw.io's standalone upstream, deferred larger runtime upgrades, and preserved local approval gates; pins and notices track only adopted material.

- Added a shared harness-aware vision-child policy: preferred Luna, Haiku and Gemini Flash families with owner-ordered providers, native Codex/Claude Code/Copilot/agy routes, runtime ID/image-path checks and bounded contexts. Provider authorization and delegation gates remain explicit; no automatic model retry ladder or installed configuration changes.
- Added `document-extract` for schema-driven PDF/PNG/JPEG fields and repeating records, with original-source evidence, explicit uncertainty, exact decimal values, a stdlib JSON/CSV exporter and an existing-xlsx handoff. Reuses document-to-markdown's local parsing helpers and privacy gates; no new parser or cloud backend. Added an authored synthetic fixture, export checks and a source-to-result oracle.
- Simplified document-to-markdown's ordinary routing to native extraction, structural parsing and targeted approved vision while retaining specialist/Office routes. Replaced stale table-extractor handoffs, removed score-based table dropping, and preserved financial section/currency/period meanings. Installed copies and parser versions are unchanged.

- Made lean verification the canonical policy in `agent-guardrails`: every check needs a named reachable failure, an independently justified expected result, and the cheapest stable seam; default zero new tests when applicable coverage exists, otherwise one focused test per uncovered behavior. No automatic broad suites, certification matrices, coverage quotas, mutation campaigns, or repeat-until-green. Passing evidence is reused while the relevant code, tests, inputs, and environment still match (an identical tree is one sufficient case, not the only one), so parent/reviewer handoffs, commits, and identical-content merges no longer force duplicate reruns; a rerun needs a relevant delta or a specific hypothesis. A failure stops at the named failure instead of widening scope. Test retirement is limited to explicitly retired behavior with genuine-duplicate consolidation that preserves real numerical, permission, persistence, and public contracts; AI authorship alone is not deletion evidence. `AGENTS.md` now routes to the skill by name with the no-expansion/no-redundant-rerun essentials.
- Aligned the verification consumers with that policy. `write-implementation-plan` assigns each validation unit as a minimal chain — named failure, independent oracle, one focused check or explicit evidence reuse, invalidating delta — and rejects generic matrices. `orchestrate-implementation` and its worker/reviewer briefs carry the exact validation scope and budget into initial, fix, and resume briefs without child widening or parent duplicate reruns. `verification-before-completion` now requires applicable claim-matched evidence (current observation for current-state claims) instead of an unconditional fresh rerun, while keeping evidence-before-claims. `merge-worktree` accepts still-applicable proof on identical integrated content and still verifies actual integration, ref, and artifact identity fresh.
- Added `project-verification` (skill authoring): an explicitly invoked generator/maintainer for portable project-local `verify-<project>` recipe skills documenting launch to a usable state, read-only readiness, concrete drive and persisted-state read-back, independently derived expectations, and owned cleanup, starting from one important journey and demonstrated only within existing execution authorization (otherwise labeled draft/unproved). Update mode is scoped to changed or proven drift with product regressions reported, never masked. Adapted from Cursor's pstack `create-verification-skill`/`maintain-verification-skill` at `f713f14203cd6420cec13cd7c55c32d598dbab68` (MIT, Copyright (c) 2026 Lauren Tan); pstack's daily-audit, verifier-swarm, and full-feature defaults are not adopted, and recipe maintenance grants no product-repair or execution authority.
- Copied the two 2026-10-16 research notes (agent-written test value; project verification skills) into `project/research/` unchanged as the historical evidence for these changes.
- Changed `orchestrate-implementation` worktree placement from repository-adjacent roots to the host-resolved `${XDG_STATE_HOME:-$HOME/.local/state}/worktrees/` root. Native Pi/Paseo retain their managed subdirectory layouts; parent-created paths distinguish source checkouts and runs. Host configuration requires separate approval; existing worktrees remain in place and unsafe/off-root new allocation still blocks.

Explicit/configured host selection still wins over verified current-host detection; unsupported selected capabilities pause without silent fallback.
