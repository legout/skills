# Changelog

Notable changes to the skills catalog are recorded here. Versions apply to the
whole catalog, not individual skills. A version is published only when its
matching Git tag exists.

## Unreleased

- Added a shared harness-aware vision-child policy: preferred Luna, Haiku and Gemini Flash families with owner-ordered providers, native Codex/Claude Code/Copilot/agy routes, runtime ID/image-path checks and bounded contexts. Provider authorization and delegation gates remain explicit; no automatic model retry ladder or installed configuration changes.
- Added `document-extract` for schema-driven PDF/PNG/JPEG fields and repeating records, with original-source evidence, explicit uncertainty, exact decimal values, a stdlib JSON/CSV exporter and an existing-xlsx handoff. Reuses document-to-markdown's local parsing helpers and privacy gates; no new parser or cloud backend. Added an authored synthetic fixture, export checks and a source-to-result oracle.
- Simplified document-to-markdown's ordinary routing to native extraction, structural parsing and targeted approved vision while retaining specialist/Office routes. Replaced stale table-extractor handoffs, removed score-based table dropping, and preserved financial section/currency/period meanings. Installed copies and parser versions are unchanged.

- Made lean verification the canonical policy in `agent-guardrails`: every check needs a named reachable failure, an independently justified expected result, and the cheapest stable seam; default zero new tests when applicable coverage exists, otherwise one focused test per uncovered behavior. No automatic broad suites, certification matrices, coverage quotas, mutation campaigns, or repeat-until-green. Passing evidence is reused while the relevant code, tests, inputs, and environment still match (an identical tree is one sufficient case, not the only one), so parent/reviewer handoffs, commits, and identical-content merges no longer force duplicate reruns; a rerun needs a relevant delta or a specific hypothesis. A failure stops at the named failure instead of widening scope. Test retirement is limited to explicitly retired behavior with genuine-duplicate consolidation that preserves real numerical, permission, persistence, and public contracts; AI authorship alone is not deletion evidence. `AGENTS.md` now routes to the skill by name with the no-expansion/no-redundant-rerun essentials.
- Aligned the verification consumers with that policy. `write-implementation-plan` assigns each validation unit as a minimal chain — named failure, independent oracle, one focused check or explicit evidence reuse, invalidating delta — and rejects generic matrices. `orchestrate-implementation` and its worker/reviewer briefs carry the exact validation scope and budget into initial, fix, and resume briefs without child widening or parent duplicate reruns. `verification-before-completion` now requires applicable claim-matched evidence (current observation for current-state claims) instead of an unconditional fresh rerun, while keeping evidence-before-claims. `merge-worktree` accepts still-applicable proof on identical integrated content and still verifies actual integration, ref, and artifact identity fresh.
- Added `project-verification` (skill authoring): an explicitly invoked generator/maintainer for portable project-local `verify-<project>` recipe skills documenting launch to a usable state, read-only readiness, concrete drive and persisted-state read-back, independently derived expectations, and owned cleanup, starting from one important journey and demonstrated only within existing execution authorization (otherwise labeled draft/unproved). Update mode is scoped to changed or proven drift with product regressions reported, never masked. Adapted from Cursor's pstack `create-verification-skill`/`maintain-verification-skill` at `f713f14203cd6420cec13cd7c55c32d598dbab68` (MIT, Copyright (c) 2026 Lauren Tan); pstack's daily-audit, verifier-swarm, and full-feature defaults are not adopted, and recipe maintenance grants no product-repair or execution authority.
- Copied the two 2026-10-16 research notes (agent-written test value; project verification skills) into `project/research/` unchanged as the historical evidence for these changes.
- Changed `orchestrate-implementation` worktree placement from repository-adjacent roots to the host-resolved `${XDG_STATE_HOME:-$HOME/.local/state}/worktrees/` root. Native Pi/Paseo retain their managed subdirectory layouts; parent-created paths distinguish source checkouts and runs. Host configuration requires separate approval; existing worktrees remain in place and unsafe/off-root new allocation still blocks.

- Simplified `orchestrate-implementation` around approved plans/issues, Pi-only children, thin host adapters, and committed-result handoffs. Native/Paseo profiles must actually run Pi, and T3 selects a Pi driver. Explicit/configured host selection still wins over verified current-host detection; unsupported selected capabilities pause without silent fallback. Removed mandatory scouts, policy menus, and unconditional reconstruction. Reconciled the rewrite with the concurrent shared-root/exact-role-pair policy: every mutation/review/candidate worktree stays under `<repo-parent>/worktrees/<repo-name>/`, model/thinking resolve per field (run/lane → project → global → defaults), and unsupported roots/pairs block without changing allocators or silently falling back. Fresh reviewer contracts remain inline; optional intercom messaging does not replace native lifecycle/placement.
- Added the `t3-delegate` adapter for T3-hosted Pi read-only children, with async notifications, stable per-round request IDs, fresh delegated follow-ups, and pending/nested-run ownership checks. Mutation is explicitly blocked while `delegate_task` lacks documented isolated workspace binding; a path or `cd` in a prompt is not binding, and top-level threads are not a fallback. Cancellation can happen before handoff and is separate from destructive cleanup.
- Supervised execution now prepares and reviews an isolated candidate before pausing for target integration; explicit user restrictions still win and publication remains separately authorized. Unique result refs preserve source commits before native finalization; fixes use descendant commits/delta review, and dependent lanes consume accepted candidate endpoints. Patch-only recovery retains byte/digest/tree/hook checks and full-replacement handling. Updated handoff integration tests, positive/near-miss/host-decision evals, and the still-PENDING live native fixture; offline checks do not claim live host acceptance.
- Reframed the `new-test` obligation around independence-first validation: one focused test whose expected values are derived from the approved spec, acceptance criteria, or an independent oracle rather than from reading the implementation, with ordering left to the worker instead of mandated test-first. Failing-test-first is retained for bug repros and characterization pinning before behavior-affecting refactors. `orchestrate-implementation` gains a cheapest-check ladder (types/lint/build, then an existing focused check, then a new focused test), a seam preference that favors the integration seam at equal cost and forbids mocking the unit under test, and generated-test reviewer failure modes (mirroring implementation structure, over-mocking, relaxed assertions, hardcoded implementation output). The manifest/brief, Pi dispatch, and `write-implementation-plan` references now name independently derived expectations and limit failing-first to bug repros and refactor pinning.
- Changed `check-skill-sources.sh` so upstream branch drift is informational after pinned paths and vendored hashes validate; `--strict-upstream` opts into failing freshness audits. No source pins were changed.
- Made `document-to-markdown` semantic-fidelity-first: page/region routing defaults for local Docling and MinerU, source-grounded acceptance checks, targeted approved vision escalation, candidate/provenance preservation, and explicit uncertainty. Added portable conversion/render/crop helpers and structural artifact checks; Office routes and existing OCR/internal-vision invocations remain supported. Structural checks and model confidence do not certify semantic correctness.
- Added visible Herdr Pi sessions and Paseo-hosted Pi workspaces alongside native Pi subagents. Herdr admission verifies the fresh session and launched pane before mutation; Paseo binds repository/workspace explicitly and distinguishes agent-scoped callbacks from top-level result collection. Durable handoffs precede cleanup, hidden untracked/submodule changes block acceptance, and optional patch recovery preserves complete bytes despite Git display/whitespace preferences. Verified same-tree/environment evidence can be reused; native automatic finalization does not grant parent-requested cleanup authority.
- Added original MIT-licensed `docx`, `pdf`, `pptx` and `xlsx` skills with uv-managed helpers for tracked Word edits/comments, independent PowerPoint slide/chart copies, Excel formula recalculation/error reporting, PDF forms/flattening/passwords and portable Office/PDF rendering. Added advanced references and a real-file regression check; no Anthropic implementation files are included.
- Added `origin_projects` provenance to `second-brain` through repeatable `--origin-project` on `add`, `idea`, `capture` and `page`. Page revisions retain and merge origins; different capture origins create linked immutable snapshots. Project/global routing and folder layouts remain unchanged.
- Moved `document-to-markdown` and `second-brain` into the `tools-and-research` category; skill names and invocations are unchanged.
- Moved default planning-artifact paths from `docs/` to the `project/` namespace (`project/research|adr|specs|plans|tickets/`, `project/agents/`), separating delivery artifacts from product documentation; legacy `docs/` installations are grandfathered and never auto-migrated. `planning-contract` records the namespace rule; consumers reference both.
- Standardized specification and plan filenames as `YYYY-MM-DD-NNNN-slug.md`, with shared work-item numbering for linked artifacts.
- Added catalog-wide semantic versioning, with `0.1.0` prepared as the first version.
- Added support for `VERSION`-based catalogs and first releases in `make-release`.
- Included the existing 34-skill catalog as the initial baseline, including planning, implementation, verification, and review guardrails.
- Added human- and agent-friendly writing rules to `second-brain` and its new-vault schema, preserving source fidelity, capture hashes and each wiki's configured language.
- Made ordinary `second-brain` persistence require maintained-page compilation or a justified deferral, preserving explicit capture-only and read-only scopes. Split advanced workflows, capture/history safeguards and retrieval maintenance into directly linked references; new-vault schemas and project hooks carry the same contract. CLI commands and existing owner schemas are unchanged.

Legacy flat notes stay in place and remain valid search, link and supersession targets; source captures and maintained-page layouts are unchanged. Callers that glob only flat note filenames must adapt to the daily layout.

Existing schemas, assets and links are not migrated.
